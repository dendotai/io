# The Sound menu's measured values

A ticket that copies a value takes it from here; how a value is read, and why not with a script, is ADR 0002. Every frame below comes from the Accessibility tree of the open Sound menu on macOS 27.0.1 on the built-in display, in points, with the top-left corner of the menu's window as the origin. The frames are the same in Light and Dark Mode and for every output in use, except where a cell says otherwise. Each look comes from one 2x screenshot crop in Light Mode.

## Device row symbols

Read on macOS 27 on a `MacBookPro18,1` in Light and Dark Mode, with the Input section shown by Option held as the menu opens (the route in #83). Each glyph matches a rendering at 13 pt semibold within 1 px of ink box and about 2% of total ink. `display`, `macbook.gen2`, and the AirPods symbols are hierarchical, their screen fill about 0.26 of the glyph colour where the default secondary layer is 0.30.

| Row                                    | Sound menu                                                    | io                                                   |
| -------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- |
| Built-in speakers and microphone       | `macbook.gen2`                                                | same                                                 |
| External Headphones                    | `headphones`                                                  | same                                                 |
| External Microphone                    | `macbook.gen2`                                                | `headphones`, reason in the code                     |
| Studio Display speakers and microphone | `display`                                                     | same                                                 |
| Aggregate or virtual, output           | `speaker.wave.2.fill`                                         | same                                                 |
| USB sound card, output                 | `speaker.wave.2.fill`                                         | same                                                 |
| USB sound card, input                  | `mic.fill`                                                    | same                                                 |
| iPhone microphone, wired or not        | `mic.fill`                                                    | `iphone.gen1` to `gen3` by model, reason in the code |
| AirPods Max, output and input          | `airpods.max`                                                 | same                                                 |
| AirPods Pro, output and input          | `airpods.pro`                                                 | `airpods.pro.gen3`, the same pixels                  |
| AirPlay receiver                       | one row per receiver, its own symbol (Apple TV, HomePod, Mac) | one `airplay.audio` row, reason in the code          |

Not compared, for lack of a device: Bluetooth headphones not made by Apple, and a display over HDMI or DisplayPort.

A grey read from the menu glass changes with what is behind the menu; one plain colour behind both menus, on the menu bar's display, makes a capture read the same on any desktop.

### Size, spacing, and animations

Read on macOS 27.2 in Dark Mode from recordings of the Sound icon beside io's icon, on the Studio Display's menu bar at about 30 fps. Ink is at 2x.

The Sound icon's symbols match a rendering at 14 pt, medium weight: the same ink box within 1 px for each symbol in the size table on #36, the same stroke widths (3 px per wave at 2x), and the same total ink within 0.1%.

The Sound item's frame is 22 pt wide with 16 pt to the next system item's frame; a third-party item's frame has 4 pt to its neighbour's. From the ink of `speaker.wave.3.fill` at 0.34 to its neighbours' ink, the Sound icon has 37 and 43 px, which io's item matches at 32 pt wide.

io matches each change in the same recording, within about 100 ms:

| Change                                    | Sound icon                                                     |
| ----------------------------------------- | -------------------------------------------------------------- |
| Volume only, in one output or between two | the waves fade to the new volume, about 400 ms, with no shrink |
| To or from the slash, mute on or off      | the symbol shrinks and the new one grows                       |
| Headphones, mute on or off                | the symbol stays about the same size                           |
| Output with another symbol                | the old symbol shrinks and the new one grows                   |

At about 30 fps the recording cannot time the lengths in the table on #36; it compares io with the Sound icon frame by frame.

The Sound icon's change is the system's symbol replace by layer, read frame by frame in a window at 120 fps and matched by io with Core Animation on one template image view per symbol layer (`io/MenuBarIcon/MenuBarIconView.swift`, `io/MenuBarIcon/MenuBarIconPieceView.swift`, `io/MenuBarIcon/MenuBarIconPieces.swift`). Neither system transition fits the menu bar: `NSImageView` draws the old symbol at the new symbol's left edge, which moves it sideways by half the width difference when the two differ in width (speaker and slash: about 4.5 pt), and a SwiftUI `Image` keeps each symbol centred but commits a frame from io's process for each step, which the menu bar blocks for about 700 ms after an output change while its own Sound icon changes, so the AirPods and headphones changes stalled and jumped; the render server plays a Core Animation animation on its own. The replace, read in a plain window: a speaker's waves are erased from their middle row outward over about 225 ms, one band for all three waves, so the short inner wave goes first and the outer wave's tips last, while its body shrinks over the last 100 ms; a single-layer symbol shrinks over about 240 ms, keeping most of its size for half of that; both end at about 0.4 of the size, one frame shows neither symbol, and the new symbol's base grows out as a critically damped spring, a speaker's body settling in about 100 ms and a whole symbol in about 220 ms, with its waves and a slash in 220 to 300 ms, half their size in a fifth of that and a long tail; a slash symbol's body shrinks over about 280 ms while its slash shrinks towards its lower end over about 450 ms, and the new symbol waits for it. The headphones' slash springs in and out over about 450 ms while the headphones stay, the system's magic replace, and the headphones crossfade to the headphones cut by the slash over 300 ms as it springs in and back over 100 ms as it leaves, so the ink stays within a few percent; a wave's dim at a lower volume is 0.3 of its opacity, and the tips of the AirPods Pro 0.5. Each symbol's pieces sit on the symbol's own canvas, centred by its alignment rect on the pixel grid at 2x: the same rows and widths as the Sound icon's for the speaker, the slash, the headphones, the AirPods Pro and the AirPods Max, read in the bar. On an inactive display's bar, macOS shows io's new image with no animation, and draws io's ink at 82 where the Sound icon's is 98, as for every item outside its menu bar process, the Input menu included. With Reduce Motion on, the Sound icon fades the old symbol out and the new one in over about 370 ms; io fades over 400 ms, not rechecked beside it.

## Reading a value again

`AXPress` on the Sound item in MenuBarAgent's Accessibility tree opens the menu with any app in front, and a second press closes it; the open menu's elements report their frames in the same tree. A look is one `screencapture -R` crop at the element's frame, read at 2x. A value read on another macOS version gets its own row with that version.
